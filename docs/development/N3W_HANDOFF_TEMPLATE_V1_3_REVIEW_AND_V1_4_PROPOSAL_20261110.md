日期：2026-11-10（Asia/Singapore）
状态：REVIEW_ONLY；不是正式交接，不替代现行 V1.3，不改变生产或合并授权。
分析基线：`bce6bd82023d5f5322eea1ab363a29df8a4cadd8`。
本次仅新增本分析稿；没有修改现行模板、长期规则、当前状态或产品代码。

## 1. 结论

繁重感有直接结构依据。V1.3 把阶段交接、操作合同、审计表和长期规则混在一起，
而默认读取集进一步把大量历史记录带入新会话。
应同时精简交接内容和读取规则，仅删模板文字不能解决主要问题。

本稿给出六部分核心模板和条件附录。核心模板由 7,786 字符缩为 1,158 字符，
约减少 85%；此比较仅针对空白模板核心，不含本分析、条件附录或填写后的真实任务数据。
这不是 token 测量，也不是执行耗时改善的实测。

## 3. V1.3 的具体问题

| 位置 | 事实与影响 | 建议 |
|---|---|---|
| 全文 0～18 节 | 共 19 节；填写者需遍历大量不适用项 | 六个核心部分，其他按实际任务加入 |
| 0、10、16、17 节 | NEXT_ONE_GATE 有 4 处赋值；LIVE_MUTATION_DEFAULT、BOARD_ACCESS_DEFAULT 也各 4 处 | 同一状态只维护一次，启动语引用它 |
| 3、4、9 节 | 普通源码任务也面对部署、服务、板卡、回滚字段，且要求不适用字段逐项说明 | 删除无关字段；涉及实机时强制加入相应模块 |
| 8、10～14 节 | 授权、操作、边界、终态、后续行动分散重复；正文同时存在低风险修复可继续和 AUTO_REPAIR_AFTER_FAIL=false | 合并“执行范围”和“下一步”；按失败类型明确处理 |
| 10、12、14 节 | 将下一 gate 默认设为不可自动进入 | 提议按完整授权任务组织连续开发；真正边界仍保留，须同步修订上位规则后生效 |
| 18 节 | 审计表预填大量 PASS 和 ready=true；未通过适用项就要求 ready=false | 审计实际检查后再填；区分“交接信息完整”和“下一动作可执行” |
| 16 节 | 默认列出完整 working context、current state、index、known failures | 路径＋章节／条目＋读取原因；有缺口时再扩大检索 |
| 模板与工作上下文 | 模板四次写 1.5；上下文头部有 1.9、1.8 等阶段段落，正式标题仍为 1.5 | 规则版本集中声明，交接引用实际 blob，不重复写死版本 |
| 工作上下文维护约定 | 文件声明仅保留稳定约定，实际在主标题前已有约 59,050 字符阶段记录 | 稳定规则与阶段记录重新分离；迁移保留历史和来源，不直接删除证据 |

“交接信息完整”与“可以立即执行”必须分开：等待 CI、缺少实机授权、真实阻塞都可以完整交接，
但不能因此宣布 CI 通过或允许生产操作。这个区分能避免为了完成交接而制造额外验收。

## 5. 条件附录：需要时才加入

附录应引用已有可读执行包，避免在交接中再复制整套命令。
执行前必须实际读取并核对所引用包，不能仅凭链接存在就判定安全。

| 触发条件 | 必须补充的内容 |
|---|---|
| 实机只读检查 | 目标公开安全身份、允许的访问方式、上次观测时间和证据、需要重查的状态；不得为填写交接而擅自访问实机 |
| T1／板卡／服务写入、升级或恢复 | 精确目标与候选摘要；授权来源、目标和有效性；claimed/consumed/superseded 状态；变更前基线；回滚包与摘要；允许重启／重试范围；失败后的最后成功步骤、服务变化和恢复状态 |
| 同一 boot 无线测试 | 本次 boot 的公开安全绑定、供电及位置、只移动哪个节点、禁止插 USB／重启等实际实验约束 |
| 固件或发布产物 | 来源 SHA、配置／工具链绑定、产物 ID／摘要和必要 manifest；源码、构建、部署与实机证据分别标记 |
| 等待 CI／复核 | PR＋exact head、相关 run 直链、适用检查状态、未完成复核、已轮询次数；换会话不成为无意义重复轮询的理由 |
| 生产版本判断 | 分别引用当前生产组成、组件升级回滚基线、不可变 Stack release；只列下一任务实际依赖的对象，不合并概念 |
| 关键资料未归档 | 内容、缺失原因、可恢复位置／摘要、补救步骤；不能写成已完整保存，不能绕过现行归档阻断规则 |

私有地址、凭据、原始设备身份等继续留在私有上下文；公开交接只保存必要的脱敏引用。
直接实机操作包必须保留完整自包含安全信息，不能用篇幅目标删掉授权、回滚或结果验证。

## 6. 新会话应该怎样读

推荐顺序（规则调整后生效）：

1. 读取交接和适用 AGENTS.md，确认任务、证据位置、允许范围和停止条件。
2. 读取稳定工作规则；同一会话内复用已核对版本，发生相关变化才重读。
3. 读取“本任务必读”中的具体章节和相关源码／测试；必读数量是软建议，不限制必要覆盖。
4. 对即将使用的 main／候选／PR 或产物做最小状态核对。
5. 只在证据缺失、冲突、分支变化或任务扩展时，扩大到当前状态、已知问题及历史记录。

CURRENT_STATE 留当前有效摘要和历史入口；INDEX 留目录映射，不再复制状态正文。
KNOWN_FAILURES 保留完整知识，但交接定位相关 KF 和全局适用防护；未看全文不能声称全量审查完成。
长期上下文只存稳定约定，不追加每次候选 SHA、服务观测和下一 gate。
这一做法仍使用现有文件，不另建 active-stage.yaml 或另一套并行事实源。

## 7. 落地范围和兼容性

必须联动的最小范围：

- 正式模板：以六部分核心＋条件模块替代固定 19 节；旧实例继续作为历史证据。
- N3W_PROJECT_WORKING_CONTEXT.md：对齐唯一有效模板版本、交接内容、最小读取集和授权内连续推进规则；单点声明规则版本。
- 仓库开发效率文档：对齐“一个对话一个 gate”等与连续推进方案冲突的约定，不借此改动产品或 CI 策略。
- 如仍有其他上位交接规则或自动校验依赖旧字段，应定位并同步处理。

本轮对 NEW_CHAT_HANDOFF_STANDARD.md 的当前 main 路径读取返回 404；不能据此假定历史标准失效，
也不能把历史版本重新当成当前模板。本轮未全仓扫描所有自动检查，推广前必须查清字段／版本依赖。

大文档整理宜分开实施：先去除模板重复并使按需读取合法，再把历史记录迁移到可追踪的归档。
迁移前确认当前事实唯一来源和入站引用；不能直接把文件头的 Latest 当成最新真实运行状态。
本轮不执行这些迁移，不把候选规则宣称已生效。

## 8. 候选方案的桌面覆盖检查

这是人工覆盖分析，不是实际会话测试、自动测试或 CI 结果。

| 场景 | 轻量交接保留什么 | 仍需停止的位置 |
|---|---|---|
| 局部源码修复 | 目标、源码 SHA、事实、相关测试、范围、下一步 | 实质设计取舍、范围扩大、未授权合并 |
| CI 尚未完成 | exact head、run 链接、pending 项、复核需求 | 依赖未通过检查的动作；不为交接重跑 |
| 实机写入前交接 | 核心＋目标／授权／候选／基线／回滚附录 | 未获适用授权、目标或摘要不符 |
| 写入失败后切换会话 | 最后完成动作、授权消费、服务变化、恢复状态、最小诊断入口 | 不重放已消费授权，不擅自重试 |
| 主线发生变化 | 冻结任务源码与当前 main 分别记录、判断差异影响 | 暂停依赖过期证据的动作，不自动换源 |

后续自然发生的 2～3 次交接中，记录实际读取字符／token（工具可提供时）、恢复所需调用、
是否重做检查、是否遗漏关键边界。目标是减少重复读取和无效停顿；
本轮不宣称已验证实际节时比例，不为验证模板额外启动固件编译或实机任务。

## 9. 本轮保存与验证边界

- 变更：仅 1 份 PUBLIC_SAFE 分析与候选文档；源码 0、测试 0、产品配置 0、私有证据 0。
- 校验：文件体量与重复字段统计；候选六部分覆盖检查；无真实凭据和私有 locator。
- 未执行：正式模板替换、规则迁移、自动校验器适配、CI、实机、生产写入、合并、发布。
- KF：本轮为工作流设计评估，不新增产品故障编号。
- 归档形式：独立 review 分支上的 Git 文件；不是已批准规则。
- 下一入口：审阅并决定是否推广 V1.4；实施时以当时 main 重新核对相关规则。
