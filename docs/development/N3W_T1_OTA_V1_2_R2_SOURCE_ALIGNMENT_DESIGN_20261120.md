## 首个候选与基线

首个完整候选只替换 HA 镜像。验收范围仍包括实际停启的 Manager、依赖的 Broker 业务路径及真正触及的受保护数据。采用现有 Manager 产品入口、受限 Unix socket、宿主特权执行器和已有事务记录。Manager、Broker 镜像继续是基线组合中两项。后续复用 Manager Generic V2，再依次验证 Broker 与多组件兼容组合。

现有 `main` 的 `HaUsbIpcExecutor` 能基于宿主解析创建准备事务、接受安装意图和返回阶段；旧栈增加了后台准备、宿主备份、导入和回滚。R3 从 `main@4fde1b7c5cc0aa224fa3574b8b4cc638edd93647` 建立干净实现分支，R4 按下述边界选择性引入旧原语及测试。保留 `V2StateStore` 的目录锁和 HA 事务记录。从正常入口验证每一批的可达性和与 Generic V2 的互斥。

## 四阶段接线

| 产品阶段 | 负责代码与主要调整 | 持久事实与中断后动作 |
| --- | --- | --- |
| 在线准备 | Manager 只提交发布意图。宿主 resolver 使用经过验证的发布输入及运行身份。准备后端从 #807 提取非破坏性的介质、工件和空间原语。执行器从实际动作推导安装和回滚各自触及的功能、数据与取证方法。 | 记录发布组合、规则版本、本机基线、原盘与候选身份和双向空间。准备中止时旧版继续运行。只在可用的已有文件系统为本事务创建 `N3W-OTA/<事务标识>/`，原盘不明确时停在准备。 |
| 建立恢复点 | 宿主安装入口复核本次事务和身份。沿用 #807 的 U6 前代校验、U7 静止备份和 U8 恢复条件，把备份前服务操作接到宿主持久事务上。 | 在第一次停服前先写恢复意图、原运行组合、受影响/需启动的服务和启动方法。普通异常、进程重启、开机均用同一回退入口。材料未完成时保持旧内部镜像，按实际状态重启必要服务并验证旧版。 |
| 切换和试运行 | 宿主逐组件登记意图，依赖工作由本地规则决定。先用 U10/U11、U13B 中经复核的镜像及数据原语。 | 在释放旧镜像前确认证据齐备。在允许新版或迁移写入前落盘“可能写入”边界。重入时在同一事务锁下核对运行镜像、容器、挂载和持久意图。旧数据未写入则优先直接启动或只导回旧镜像。可能已写入则静止写入方并恢复同一恢复点后再启动。确实需要原盘时进入恢复等待。 |
| 验收和结束 | checker 提供带来源的可核对事实，执行器选择提交或回滚。宿主在已完成验收后持久确认实际组合。状态接口按阶段只读投影。 | 安装端三问均满足后持久记录 `SUCCESS`。旧版恢复健康且有本次新证据后持久记录 `FAILURE`。恢复、缺盘、证据待补为过程。提交后的 USB 卸载和 UI 刷新独立收尾，不改变持久结果。 |

已经停服且旧镜像和数据仍在时，安全恢复不依赖 U 盘可用、Manager/HA 进程、发布投影或 checker 的可用性。宿主恢复调度先接上持久事务，从启动路径和正常失败路径调用同一实现。独立 IPC 导出目录保护 Manager 的访问边界；目录、套接字或投影初始化失败须覆盖“宿主仍能恢复”的启动测试。执行动作和状态查询间不传递写权限。

## 状态、兼容边界与验收

- **仅维护一份事务主记录。** 延用已有宿主事务存储和跨进程锁。记录规则版本、恢复意图、实际完成事实、进展、补验预算以及动作身份。USB 上的附加记录提供材料核对。新执行器只在没有活动事务时正常切换，能够读取受支持的旧记录与授权消费事实。旧终态可查阅，旧活动事务由该事务原执行与恢复路径处理。遇到未识别或损坏记录暂停新安装，保护仍可运行的服务与原材料。已经消费的授权从不重放。
- **防止附加信息误判。** 核心阶段先由宿主事务及恢复事实产生。准备容量仅在适用准备阶段读取，失败时附加字段降级。状态查询不会发自检消息、消费授权、写盘、改事务或管理服务。
- **只保留第 6 节三问。** 每笔核对实际承载业务的三组件身份。确实影响收数时优先关联自然消息，必要时由执行器使用停服前已验证的本机自检。数据真正受影响时核对挂载来源及预先取样的既有内容。静止备份和恢复的完整性校验仍在对应写入边界执行。运行中必检项按 `PASS`、`PROVEN_FAIL`、`EVIDENCE_UNAVAILABLE` 处理，持久保留补验预算。观察异常只记录诊断；只有适用必检事实在限定取证范围内不能满足才影响新版提交。
- **明确签名发布的产品准入。** 已查看现有 Manager 和旧宿主 resolver 的 `signature_status` 判断。该字段只代表上游提供的状态。R4 可用测试输入联调恢复，R6/R9 需证明宿主从受限来源校验签名索引和发布清单，信任根及执行器可信更新路径可验证。发布签名、信任根配置及客户启用保持独立授权。测试输入不可进入客户发布。

## 实现顺序和成对回归

| R4 批次 | 先行改动 | 最少验证 |
| --- | --- | --- |
| 1. 首次停服责任 | 补事务写入边界和共享锁下的恢复分派。把可用的旧版启动能力接到宿主入口。 | 意图落盘前、中、后退出；停止部分服务后退出；旧镜像仍在且原盘缺失时恢复；已提交事务重入只收尾；并发控制命令不重复启动动作。 |
| 2. 原盘、材料与实际写入边界 | 接非格式化准备、独立前代工件读回和静止数据备份。复用需要的 U10/U11 与 U13B 原语。 | 非空盘与盘符变化、错盘、文件系统只读和空间不足；停服后备份失败恢复；新版可能写数据前后分别断电；旧数据恢复、工件损坏、慢盘有进展。 |
| 3. 按影响验收和状态解耦 | 上线事务只读投影、三问判定和实际产品入口闭环。 | 观察故障与真实业务失败成对；只读状态没有动作；自然消息、零节点或空历史；已恢复而证据暂缺时维持服务；提交写入前后中断和 USB 收尾失败。 |
| 4. 其他组件及整套组合 | 接 Manager、Broker 和多组件恢复顺序；候选经统一发布准入。 | 单组件无关检查不启用；多组件最后一项失败，恢复此前已变更部分，核对完整前代组合。 |

R5 汇总各批次及 V1.2 第 9、10 节的覆盖。两项 R1 中受执行环境限制的基线测试需在具有对应能力的隔离环境或适用 CI 复核。R7/R8 的测试目标是独立于旧授权的备用 T1；R9 将产品证据绑定至 R6 的精确候选。
