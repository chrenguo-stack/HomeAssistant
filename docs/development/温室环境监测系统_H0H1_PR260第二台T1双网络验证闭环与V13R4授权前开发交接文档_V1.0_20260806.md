## 7. 已证明根因

```text
ROOT_CAUSE=BROKER_CONNECTED_ONLY_TO_INTERNAL_BRIDGE_PREVENTED_EFFECTIVE_HOST_PORT_PUBLISHING
GENERIC_DOCKER_LOOPBACK_FAILURE=false
DOCKER_DAEMON_CONFIGURATION_FAILURE=false
SS_FALSE_NEGATIVE=false
DUAL_NETWORK_REMEDIATION_VALIDATED=true
```

对照证据：

| 网络结构 | docker-proxy | DNAT | 宿主回环 TCP/MQTT |
|---|---:|---:|---:|
| 仅 internal bridge | 0 | 0 | 失败 |
| 单一普通 bridge | 1 | 存在 | 通过 |
| 普通发布网络 + internal 私有网络 | 1 | 存在 | 通过 |

因此，V13R4 不得继续采用“Broker 只连接 internal 网络并发布宿主端口”的结构。

## 8. V13R4 候选生产架构

```text
greenhouse-pr260-private:
  internal=true
  gw-priority=0
  members=greenhouse-manager,mosquitto

greenhouse-pr260-hostloopback:
  internal=false
  gw-priority=1
  members=mosquitto-only

published-port:
  127.0.0.1:1883 -> mosquitto:1883
```

必须保持：

1. Home Assistant 继续使用 host 网络并连接 `127.0.0.1:1883`；
2. Manager 只连接 `greenhouse-pr260-private`，不得连接 hostloopback 网络；
3. Broker 同时连接两个网络，默认网关由非 internal 发布网络承担；
4. 不发布第二台 T1 的局域网 1883；
5. 不发布任何 8883；
6. 暂不关闭匿名 MQTT；
7. 不下发节点凭据；
8. 不修改 Docker daemon、sysctl、iptables 或 nftables 配置；
9. 不修改第一台 T1、节点或板卡。

6. 宿主 1883/8883 均不存在；
